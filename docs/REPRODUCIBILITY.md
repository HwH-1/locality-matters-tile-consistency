## 2. The one external dependency: the CA-AKF reference pipeline (已核实)

`src/tc.py` builds CA-AKF and SC-AKF on top of an external reference implementation
(`filters.py`, `methods.py`, `structure.py`, `metrics.py`). It looks for that package on
`sys.path` and honours the `CAAKF_REF` environment variable:

```bash
export CAAKF_REF=/path/to/TheVisualComputer_JLR/03_experiments   # directory containing src/
python3 -c "import sys; sys.path.insert(0,'src'); import tc; print('ok')"
```

If neither the variable nor a usable `src` package is on the path, `tc.py` now raises an
`ImportError` naming both (this was a defect in an earlier revision: the path was hardcoded
to `/tmp/jlr/...`, which no reader has). The reference package is **not** in this archive;
it is the JLR project accompanying the previous submission. If you cannot supply it, the
four operators that need it (`CA-AKF`, `SC-AKF`, and their use in §6.7/§6.8) cannot be run;
`AKF` (the fixed-radius control is implemented in `tc.py` itself), `LRS-AKF`, and all of
§6.9 (OpenCV methods) do not depend on it. **AI推断**: expect the `AKF`/`LRS-AKF`/§6.9
subset to run without `CAAKF_REF`.

## 6. Building the manuscript

```bash
python3 build.py        # -> paper/build/manuscript_ready.md + paper/build/manuscript.docx
```

`build.py` resolves every `[@key]`/`@key` against **`paper/refs.bib` only**, assigns citation
numbers by order of first appearance, emits the numbered References list, inserts the eight
figures at their section anchors, and calls pandoc (`pandoc 2.x`, no `--citeproc` needed).
`paper/refs_cv_additions.bib` is provenance: its 11 keys are already present in `refs.bib`
(verified set overlap = all 11, no unique keys). Keeping it beside `refs.bib` invites the
question "which file is authoritative?" — `refs.bib` is; deleting the additions file changes
nothing in the build.

Expected diagnostics from a clean build: `MISSING KEYS` absent, `UNCITED` absent. A non-empty
`MISSING KEYS` list means a citation was dropped silently — the DOCX would still render, with a
hole where the reference should be.

### 6b. LaTeX route (PDF)

```bash
python3 build.py && python3 build_latex.py
# -> paper/latex/manuscript.tex, paper/latex/manuscript.pdf, paper/latex/manuscript.log
```

`build_latex.py` reads the *same* generated `paper/build/manuscript_ready.md`, so the PDF and the
DOCX cannot disagree about wording, numbers, citations or captions. It splits the front matter
(title / author / affiliation / keywords / abstract) from the body, runs pandoc `-t latex` on the
body, then does four layout-only transformations: merges each figure's italic caption paragraph
into a LaTeX `figure` float, wraps every `longtable` in a size group (`\small`/`\footnotesize`/
`\scriptsize` by column count), inserts legal break points in long file paths and DOI strings, and
maps the handful of Unicode symbols (× → ≤ ± − § · – —) to LaTeX equivalents. It writes nothing
unless every structural anchor it expects is found exactly once, and it aborts if any non-ASCII
character is left unmapped.

What the current build reports (2026-11-04, this environment): **34 pages**, 8 embedded figures at
275–348 dpi effective, 14 tables, 36 references, 0 TeX errors, 0 undefined control sequences,
0 missing characters, no overfull box above 20 pt. Reproduce the check with:

```bash
grep -c "Undefined control sequence" paper/latex/manuscript.log   # 0
pdfinfo paper/latex/manuscript.pdf | grep Pages                   # 34
pdfimages -list paper/latex/manuscript.pdf                        # 8 images
```

The PDF is a typesetting of the manuscript, not the journal's camera-ready template: The Visual
Computer's official Word/LaTeX template could not be fetched from this sandbox (**待核实**), so the
submission artefact remains `manuscript.docx` and the PDF is for proof-reading and for any
PDF-only submission path.

### 6c. Reference integrity audit and the acceptance battery

```bash
python3 audit_refs.py      # every reference re-read from the registry that owns its identifier
python3 verify_final.py    # 23 checks over manuscript.md, the built DOCX and the built PDF
```

`audit_refs.py` parses `paper/refs.bib` and, for each entry, asks the registry that issued the
identifier what it actually says: Crossref for a DOI, the arXiv API for an `eprint`, DataCite for
a Zenodo/Figshare DOI (10.5281 / 10.6084). It compares the title, **every** author surname and the
year, and prints both strings on any disagreement — it never rewrites an entry. Current result:
**36 consistent, 0 mismatched, 0 unverifiable** (`paper/REF_AUDIT_LOG.txt`).

This audit found two real defects, which is why it is part of the build and not an extra:

1. `huang2018tiling` listed four wrong author names (Benjamin/David/Lance/Kevin — the arXiv record
   says **Bohao Huang, Daniel Reichman, Leslie M. Collins, Kyle Bradbury**) and had no identifier,
   so the printed reference could not be resolved. Both fixed from the API response.
2. `split_fields()` in `build.py` advanced past the *next* field name whenever a value was
   unbraced, so `gastal2012amf` lost its `doi` after `month = jul,` — the reference list printed a
   venue and page range with no link, and the build still reported zero problems.

`verify_final.py` covers the failure modes those two bugs exposed: no unresolved `[@key]` or
`{{TOKEN}}`, no bare cite key in the generated markdown **or in `pdftotext` output of the PDF**,
no bib field silently dropped (raw `.bib` field names vs. parsed set), every printed reference
carrying a DOI/arXiv identifier, table captions 1–14 all cited in prose, all 8 figures captioned
and referenced, every `Section X.Y`/`§X.Y` cross-reference resolving to a heading of this paper,
the DOCX abstract at 248 words, and the §6.9 region still containing the machine-generated draft
byte-for-byte. It exits non-zero on any failure.

Registry lookups need network access. If `api.crossref.org`, `export.arxiv.org` or
`api.datacite.org` is unreachable, `audit_refs.py` marks the entry `UNV` rather than guessing —
treat "unverifiable" as an unfinished check, not a passed one.

Two IEEE records (ICCV-98 bilateral, AVSS-2005) carry `issued: [[null]]` in Crossref; their year is
taken from the conference name or the DOI slug, never from `created`, which is the date the DOI was
registered (ICCV-98's record was created in 2002).

## 7. Known non-reproducible or intentionally unstable items (已核实)

1. **§6.9 Perona–Malik determinism.** The finding *is* non-determinism: repeated calls on
   identical input differ (`out/cv_bug.jsonl`). Any rerun reproduces the phenomenon, not the
   same deviation magnitudes; the manuscript reports medians over the shipped records.
2. **§4.5 mechanism probe.** `tau_drift` (`src/tc.py:211`) has no caller in the release and
   no record in `out/`. §6.3 therefore quotes no per-tile $\tau$ ratios; §4.5 states the test
   as a proposal. Do not expect a number from it.
3. **Timing numbers.** Wall-clock figures in §3.2/§6.7 were recorded one evaluation mode per
   process on a shared host and are load-dependent. Peak RSS is the quantity the argument
   uses; do not re-derive a timing claim.
4. **LRS-AKF at $n=8$.** That run was lost to a machine restart (§3.2 states this), so the
   fit and the check coincide for it and no predictive content is claimed.
5. **`out/broad.jsonl` (6 rows) vs `out/broad_all.jsonl` (576 rows).** The former is a pilot;
   §6.8 uses the latter.
